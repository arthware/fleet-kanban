  prompt-ready reducer path remains narrower than explicit `hook.to_in_progress`.
- Codex deferred startup input still exists in the manager, but no current adapter populates it. The manager sequencing is

  `agentSessionId`; Gemini timeout leaves the running attached session id as `null`.
- Claude overseer sessions derive a deterministic id from `workspaceId`, `agentId`, and generation. With no transcript
  they launch fresh under that id; with a transcript they resume that id and send an empty prompt.
- Transcript parsing is pinned with recorded fixtures for Claude and Codex. Gemini's current bug is pinned as

- Usage parsing is pinned with recorded fixtures for Claude and Codex. Gemini currently reports absent because it has no
  usage deriver, with a skipped known-red desired test for card 4.
- Gemini's submit delay is pinned at 300 ms; Codex and Claude retain the default 50 ms delay.
- Resting states covered: no transcript (`readAgentTranscript` absent), no usage/transcript deriver, Gemini id timeout,

## Findings

1. The card premise about `deferredStartupInput` being a current Codex adapter behavior is stale. The field and manager
   path remain, and existing tests cover it through faked launches, but no adapter in `agent-session-adapters.ts`
   currently returns `deferredStartupInput`.
2. Codex prompt-ready behavior is stricter than the card wording suggests. The detector recognizes `attention` and
   `hook`, the manager Enter flag is set for `hook`/`attention`/`error`, and the reducer only wakes prompt-ready from
   `needs_input`. In the observable manager path tested here, prompt-ready bytes do not resume a `needs_input` session
   even after Enter because the Enter flag is not set for `needs_input`.
3. Gemini transcript location knows Gemini, but transcript parsing still dispatches Gemini to the Claude parser. A real
   Gemini-shaped fixture therefore locates successfully and renders zero messages.
4. Gemini usage has no deriver at all, so `readAgentUsage` returns absent before reading the located Gemini transcript.

## Gemini Hook Delivery Experiment

Scope: hook layer only. No board was started, and ports 3500/3200 were not used. The experiment used the real
`gemini` CLI (`v0.53.0`) in `/tmp/kanban-gemini-hook.clean/work`, with the exact `settings.json` generated by
`prepareAgentLaunch({ agentId: "gemini", workspaceId })`. The generated command was:

```sh
'/Users/arthur/.asdf/installs/nodejs/24.8.0/bin/node' \
  '/Users/arthur/code/repos/tools/.fleet/cline/worktrees/7ddac/fleet-kanban@session-kinds/dist/cli.js' \
  'hooks' 'gemini-hook'
```

An observer preload recorded process start, child spawn, and `fetch` attempts while `KANBAN_RUNTIME_PORT=49321`
pointed at no live board. The preload returned an OK response for the hook ingest request so the hook layer could
complete without a board.

Observed order:

1. Gemini spawned `bash -c '<node> <dist/cli.js> hooks gemini-hook'` for `BeforeAgent`.
2. The first hook process (`hooks gemini-hook`) started, parsed the payload, spawned:
   `hooks notify --event to_in_progress --source gemini --activity-text "Resumed after user input" --hook-event-name BeforeAgent`,
   then exited 0.
3. The spawned notify process was reparented to pid 1.
4. The notify process made a `POST` to `http://127.0.0.1:49321/api/trpc/hooks.ingest?batch=1` with
   `event:"to_in_progress"` and Gemini metadata, then exited 0.

Conclusion: this evidence does not support "the second hop loses the signal" for a normal `BeforeAgent` hook. The
second process did run after being orphaned and did attempt ingest. The evidence supports the other candidate more:
Gemini `Notification` currently maps to `activity`, and `activity` does not wake a session. This experiment did not
observe a real Gemini `Notification` attention payload, so that conclusion is about the code path plus the measured
delivery of `BeforeAgent`, not a live attention-prompt reproduction.

## Missing Seams

- Hook subcommands are CLI-only. There is no exported `mapGeminiHookPayloadToRuntimeEvent` or `runGeminiHook(payload,
  ingest)` API. Smallest honest API: a pure mapper plus an injectable hook runner returning `{ response, spawnedNotify,
  ingestResult }`.
- `TerminalSessionManager` owns session-id polling timers privately. Tests can fake capture modules and timers, but cannot
  configure attempts/intervals through a public clock. Smallest honest API: inject a scheduler/capture policy into the
  manager constructor.
- Deferred startup input is manager behavior but no live adapter currently produces it. Smallest honest API: move startup
  input sequencing behind a driver/control contract and let each driver declare whether it uses it.
- Codex prompt readiness is split between adapter detector, manager Enter bookkeeping, and reducer policy. Smallest honest
  API: a stateful driver signal interpreter that owns "terminal bytes + submitted input => driver fact".
- Transcript location, transcript parsing, and usage derivation are separate dispatch tables with different known-agent
  sets. Smallest honest API: per-driver `observe` with `artifactPresent`, `messages`, and `usage`.
- Overseer deterministic identity is only observable by starting a manager with faked transcript lookup. Smallest honest
  API: expose identity planning as a pure driver/session-kind decision before spawning.
